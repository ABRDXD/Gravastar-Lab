# C++20 audit: 2026-10-24

This pass reviews the implemented P1/P2 code and fixes reproduced bugs. It adds
no new optics feature. The baseline is `083273a`; the report-path fix was saved
first as `9740933`, followed by event diagnostics/constraints in `d16fdf7` and
empty-polynomial handling in `2e213e5`. The isolated branch remains
`codex/p2-reference-optics`; the original checkout and remote main are untouched.

## Confirmed findings and fixes

### JSON report overwritten by its display image

`gravastar_trace image --output results/collision.ppm` previously accepted the
path, wrote JSON there, then replaced that same file with its PPM preview.
The command returned success despite losing the numerical report. A regression
using a 1x1 scene reproduced this behavior before the fix.

Trace outputs now require the documented `.json` extension before any output
is written. The regression checks rejection, preservation of a pre-existing
display file, and absence of a spurious manifest. Normal JSON/PPM outputs and
failure isolation remain covered by the image CLI tests.

### Refined shell events bypassed null-constraint diagnostics

Nonterminal shell crossings had their own refined state and null residual,
but only ordinary step endpoints updated the reported maximum. Refined
crossings also bypassed the configured null ceiling.

The deterministic regression uses the default toy geometry, launch position
`(t,r,theta,phi)=(0,2,pi/2,0)`, sight `(-1,0,-0.2)`, absolute/relative tolerances
`1e-6`, maximum step `0.4`, and affine budget `1.1575548858002598`.
These deliberately loose integration tolerances expose the fault; they are not
the accepted image preset.

Before the fix, an inner-shell crossing had residual
`7.0724569094012538e-6`, exceeding the reported maximum
`6.9294630298362307e-6`. Setting the null ceiling to `7e-6` still allowed a normal
affine-budget outcome. Both new regression assertions failed on that code.

Refined events now enforce the null ceiling before publication. A failed event
rejects/shortens the trial using the existing event-retry mechanism; if accuracy
cannot be maintained, the trace reports numerical failure. Every published
crossing contributes to null, energy and angular-momentum diagnostics.

With the loose `0.01` null ceiling, the corrected report maximum equals the
crossing residual `7.0724569094012538e-6`. With `7e-6`, the GCC regression now
reports numerical failure after a retry instead of silently accepting the
violation; no published crossing exceeds that ceiling. A failed trace may
retain its failed endpoint and residual for diagnosis, as before.

Historical ray reports may understate their maximum null residual because they
exclude nonterminal refined events. They are retained with their original source
digests, not relabeled as current validation. The full 128x96 sampling pilots
have not been rerun in this audit.

### Empty Bernstein input caused a segmentation fault

`reference::positive_bounds({})` built an empty coefficient vector and
dereferenced the empty result of `minmax_element`. The new regression reproduced
a segmentation fault in `reference_migration` before the fix. The function now
throws `invalid_argument` before allocation/subdivision. Existing exact degree-11
shell certificates and nonpositive-polynomial rejection are unchanged.

## Review coverage and limitations

The review covered regular and BL geometry construction, shared shell profiles,
derivative arithmetic, curvature/reference comparisons, exact Sturm/Bernstein
logic, ray stepping and event publication, CLI artifact naming and isolation,
sampling grid/mask arithmetic, process invocation, source inventories and CMake
test registration. The complete release CTest suites re-exercise these layers;
targeted instrumented checks cover the modified code paths. This is a bounded
code/test audit, not a proof that every input or numerical trajectory is correct.

Existing limitations remain: hidden multiple/grazing events are not certified;
production rays still stop at angular/central chart boundaries; GYOTO comparison,
complete image convergence and physical stability remain unestablished. The
regular angular geometry is implemented but not yet connected to the tracer.

The final test matrix and reproduction commands are recorded in
`results/p2_audit_verification.json`; current optical checks use
`results/p2_audit_optics_validation.json` and
`results/p2_audit_image_validation.json`. The audit inventory is
`results/p2_audit_source_manifest.json`. Prior geometry/performance reports remain
historical evidence for their original source trees.
